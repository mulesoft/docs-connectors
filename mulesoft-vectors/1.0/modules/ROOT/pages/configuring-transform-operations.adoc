= Configuring Transform Operations

Configure the *[Transform] Parse document* and *[Transform] Chunk text* operations. 

== Configure the Transform Parse Document Operation

The *[Transform] Parse document* operation extracts text content from various document formats including PDF, DOCX, PPTX, and other supported file types. This operation is typically the first step in document processing workflows before text chunking and embedding generation.

The *[Transform] Parse document* operation can process documents from various sources including file systems, cloud storage services, or direct file uploads. The extracted text maintains formatting context and metadata from the original document.

To configure the *[Transform] Parse document* operation:

include::connectors::partial$t-configure-operations.adoc[]
* *Document Source*
+
Enter the source of the document to parse. This can be a file path, URL, or document content.
* *Document Type*
+
Specify the document format (PDF, DOCX, PPTX, TXT, etc.). Leave blank for automatic detection.
* *Extract Metadata*
+
Select whether to extract document metadata such as title, author, creation date, and other properties.
* *Preserve Formatting*
+
Choose whether to maintain text formatting and structure from the original document.

This is the XML for this operation:
[source,xml,linenums, subs=attributes+]
----
<ms-vectors:transform-parse-document
  doc:name="[Transform] Parse document"
  doc:id="a1b2c3d4-e5f6-7890-abcd-ef1234567890"
  config-ref="MuleSoft_Vectors_Connector_Document_config"
  extractMetadata="true"
  preserveFormatting="false">
  <ms-vectors:document-source ><![CDATA[#[payload.documentPath]]]></ms-vectors:document-source>
  <ms-vectors:document-type ><![CDATA[#[payload.fileType]]]></ms-vectors:document-type>
</ms-vectors:transform-parse-document>
----

=== Output Configuration

This operation responds with a JSON payload containing the extracted text and metadata:

[source,json]
----
{
  "text": "In the modern world, technological advancements have become essential for businesses to remain competitive. E-commerce giants like Amazon and Alibaba have redefined the retail landscape through innovative use of technology and data analytics.",
  "metadata": {
    "title": "Technology in Business",
    "author": "John Smith", 
    "creationDate": "2024-01-15T10:30:00Z",
    "pageCount": 5,
    "wordCount": 1247,
    "fileSize": 245760,
    "documentType": "PDF"
  },
  "extractedAt": "2024-01-20T14:25:30Z",
  "success": true
}
----

* `text`: The complete extracted text content from the document.
* `metadata`: Document properties and information.
** `title`: Document title if available.
** `author`: Document author if available.
** `creationDate`: Document creation timestamp.
** `pageCount`: Number of pages in the document.
** `wordCount`: Total word count in the extracted text.
** `fileSize`: Original file size in bytes.
** `documentType`: Detected or specified document format.
* `extractedAt`: Timestamp when the parsing operation completed.
* `success`: Boolean indicating if the parsing completed successfully.

== Configure the Transform Chunk Text Operation

The *[Transform] Chunk text* operation splits large text content into smaller, manageable segments with configurable overlap. This operation is essential for preparing text for embedding generation and ensures optimal performance with language models that have token limits.

The *[Transform] Chunk text* operation typically follows the *[Transform] Parse document* operation in document processing workflows, or can be used independently for text segmentation tasks.

To configure the *[Transform] Chunk text* operation:

include::connectors::partial$t-configure-operations.adoc[]
* *Input Text*
+
Enter the text content to be chunked. This typically comes from the parse document operation output.
* *Chunk Size*
+
Enter the maximum number of characters per text chunk.
* *Overlap Size*
+
Enter the number of characters to overlap between consecutive chunks for context preservation.
* *Split Method*
+
Select the text splitting strategy (sentences, paragraphs, or fixed character count).
* *Preserve Context*
+
Choose whether to maintain semantic boundaries when splitting text.

This is the XML for this operation:
[source,xml,linenums, subs=attributes+]
----
<ms-vectors:transform-chunk-text
  doc:name="[Transform] Chunk text"
  doc:id="b2c3d4e5-f6g7-8901-bcde-f23456789012"
  config-ref="MuleSoft_Vectors_Connector_Document_config"
  chunkSize="1000"
  overlapSize="100"
  splitMethod="SENTENCES"
  preserveContext="true">
  <ms-vectors:input-text ><![CDATA[#[payload.text]]]></ms-vectors:input-text>
</ms-vectors:transform-chunk-text>
----

=== Output Configuration

This operation responds with a JSON payload containing the text chunks and metadata:

[source,json]
----
{
  "chunks": [
    {
      "index": 0,
      "text": "In the modern world, technological advancements have become essential for businesses to remain competitive. Companies that embrace digital transformation often see significant improvements in efficiency and customer satisfaction.",
      "startPosition": 0,
      "endPosition": 198,
      "characterCount": 198
    },
    {
      "index": 1,
      "text": "Companies that embrace digital transformation often see significant improvements in efficiency and customer satisfaction. E-commerce giants like Amazon and Alibaba have redefined the retail landscape through innovative use of technology.",
      "startPosition": 98,
      "endPosition": 345,
      "characterCount": 247
    }
  ],
  "totalChunks": 2,
  "originalLength": 1247,
  "avgChunkSize": 222,
  "processingTime": "0.125s"
}
----

* `chunks`: List of text segments created from the original text.
** `index`: Sequential number of the chunk starting from 0.
** `text`: The actual text content of the chunk.
** `startPosition`: Character position where this chunk begins in the original text.
** `endPosition`: Character position where this chunk ends in the original text.
** `characterCount`: Number of characters in this specific chunk.
* `totalChunks`: Total number of chunks created.
* `originalLength`: Character count of the original input text.
* `avgChunkSize`: Average character count across all chunks.
* `processingTime`: Time taken to complete the chunking operation.

The operation also returns attributes that provide additional metadata about the chunking process:

[source,json]
----
{
  "chunkingStrategy": "SENTENCES",
  "overlapPercentage": 10.0,
  "preservedContext": true,
  "splitBoundaries": [
    "sentence",
    "paragraph"
  ]
}
----

* `chunkingStrategy`: The method used for text splitting.
* `overlapPercentage`: Percentage of overlap between consecutive chunks.
* `preservedContext`: Boolean indicating if semantic context was maintained.
* `splitBoundaries`: List of boundary types used for splitting decisions.
