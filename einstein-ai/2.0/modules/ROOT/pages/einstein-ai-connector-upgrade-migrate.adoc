= Upgrading and Migrating Einstein AI Connector to 2.x

Upgrade Anypoint Connector for Einstein AI (Einstein AI Connector) from version 1.x to version 2.x.

== Supported Upgrade Paths

[%header,cols="50a,50a"]
|===
|From Version | To Version
|1.x |2.x
|===

== Changes

=== 2.0

* This connector requires Java 17. Java 8 and Java 11 aren't supported.
* This connector requires Mule runtime 4.9.0 and later.
* Document parsing now uses Apache Tika 4.0.0. Text extraction for some document types can differ from Einstein AI Connector 1.2.
* The connection type is now xref:einstein-ai-connector-reference.adoc#Config_OauthClientCredentials[*OAuth Client Credentials*]. Re-create the global configuration if the previous connection type doesn't load.
* The xref:einstein-ai-connector-reference.adoc#RagAdhocLoadDocument[*RAG Adhoc Load Document*] operation no longer accepts *File Path*. Provide the document in *Input Stream*. Applications that still set `filePath` must remove that attribute.
* *Prompt* is required for xref:einstein-ai-connector-reference.adoc#EmbeddingAdhocFileQuery[*Embedding Adhoc File Query*] and xref:einstein-ai-connector-reference.adoc#RagAdhocLoadDocument[*RAG Adhoc Load Document*]. It no longer defaults to `#[payload]`.
* *File Type* is an enumeration with values `PDF`, `TEXT`, and `CSV` on xref:einstein-ai-connector-reference.adoc#EmbeddingAdhocFileQuery[*Embedding Adhoc File Query*], xref:einstein-ai-connector-reference.adoc#EmbeddingGenerateFromFile[*Embedding Generate From File*], and xref:einstein-ai-connector-reference.adoc#RagAdhocLoadDocument[*RAG Adhoc Load Document*]. `URL` is no longer a file type.
* *Option Type* on those operations is an enumeration with values `FULL` and `PARAGRAPH`.
* The xref:einstein-ai-connector-reference.adoc#ChatGenerateFromMessages[*Messages*] field on *Chat Generate From Messages* accepts any payload type.
* xref:einstein-ai-connector-reference.adoc#GenerationParameters[*Logprobs*] and *Refusal* are strings.
* xref:einstein-ai-connector-reference.adoc#ResponseParameters[*System Fingerprint*] replaces *System Finger Print* in response parameters.
* These libraries are upgraded to address reported security vulnerabilities:

** The `tika-core` and `tika-parsers-standard-package` libraries are upgraded to version 4.0.0.
** The `org.bouncycastle` library is upgraded to version 1.86.
** The `log4j` dependency is excluded.

== Requirements

Ensure your system meets the following compatibility requirements before you perform the upgrade:

[%header%autowidth.spread]
|===
|Application/Service|Version
|Mule runtime |4.9.0 and later
|Java |17
|===

== Upgrade Prerequisites

Before you perform the upgrade, you must:

. Create a backup of your files, data, and configuration in case you need to restore to the previous version.
. Ensure that your environment meets the version 2.x requirements, including Java 17 and Mule runtime 4.9.0 or later.
. If an app sets `filePath` on *RAG Adhoc Load Document*, provide the document in *Input Stream* and remove `filePath`.
. If an app sets *File Type* to `URL`, change it to `PDF`, `TEXT`, or `CSV`.
. Install Einstein AI Connector 2.x to replace the operations that were previously included in Einstein AI Connector 1.x.

== Upgrade Steps

Follow these steps to perform the upgrade from Einstein AI Connector 1.x to Einstein AI Connector 2.x:

. In Anypoint Studio, create a Mule project.
. In the Mule Palette view, click *Search in Exchange*.
. In the *Add Dependencies to Project* window, enter `Einstein AI` in the search field.
. In the *Available modules* section, select *Einstein AI Connector* and click *Add*.
. Click *Finish*.
. Verify that the `mule4-einstein-ai-connector` dependency version is `2.x.x` in the `pom.xml` file, where `x.x` is the minor release and patch version number. For example, if you are upgrading to version 2.0, the dependency version in the `pom.xml` file should be `2.0.0`.

Studio upgrades the connector automatically.

== Verify the Upgrade

After you install the latest version of the connector, follow these steps to verify the upgrade:

. In Studio, verify that there are no errors in the *Problems* or *Console* views.
. Check the project `pom.xml` file and verify that there are no problems.
. Test the connection and verify that the operations work.

== Troubleshooting

If there are problems with caching the parameters and caching the metadata, try restarting Studio.

== Revert the Upgrade

If it is necessary to revert to the previous version of Einstein AI Connector, change the `mule4-einstein-ai-connector` dependency version in the project's `pom.xml` file to the previous version.

You must update the project's `pom.xml` file in Anypoint Studio.
