= Upgrading and Migrating Oracle EBS 12.2 Connector to 3.x

Upgrade Anypoint Connector for Oracle E-Business Suite 12.2 (Oracle EBS 12.2 Connector) from version 2.x to version 3.x.

== Supported Upgrade Paths

[%header,cols="50a,50a"]
|===
|From Version | To Version
|2.x |3.x
|===

== Changes in This Release

=== 3.0

* This connector is now compatible with Java 17 only.
* The source XML element is now `business-events-listener`, instead of `business-events-source`. In Studio, the source is *On New Business Event*. For more information, see xref:oracle-ebs-122-connector-reference.adoc#BusinessEventsListener[*On New Business Event*].
* *On New Business Event* now includes optional *Queue owner* and *Queue name* fields. The fields default to `APPS` and `WF_BPEL_Q`. Custom queues must use the `APPS_NE.WF_EVENT_T` payload type. For more information, see xref:oracle-ebs-122-connector-reference.adoc#BusinessEventsListener[*On New Business Event*].
* The *Event Data* field is now binary. Flows that read *Event Data* as a string must convert the binary value. For more information, see xref:oracle-ebs-122-connector-reference.adoc#Event[Event].
* The *Invoke PL/SQL REST Service* operation now returns HTTP status, reason phrase, and headers as message attributes. The XML payload is unchanged. For more information, see xref:oracle-ebs-122-connector-reference.adoc#invokePlSqlRestService[*Invoke PL/SQL REST Service*] and xref:oracle-ebs-122-connector-reference.adoc#EbsResponseAttributes[EBS Response Attributes].
* The default configuration now includes optional *Response Timeout* and *Response Timeout Unit* fields. *Response Timeout Unit* defaults to `MILLISECONDS`. When *Response Timeout* is unset, the connection uses its existing default. The *Invoke PL/SQL REST Service* operation includes *Response Timeout* and *Response Timeout Time Unit*, and uses the configuration values unless you set them on the operation. For more information, see xref:oracle-ebs-122-connector-reference.adoc#config[Default Configuration] and xref:oracle-ebs-122-connector-reference.adoc#invokePlSqlRestService[*Invoke PL/SQL REST Service*].
* The JMS configuration now includes *Read Receive Timeout Unit*. It defaults to `MILLISECONDS`, so the default *Read Receive Timeout* of `30000` is unchanged. For more information, see xref:oracle-ebs-122-connector-reference.adoc#jms-config[JMS Configuration].
* TCP client socket properties now include *Client Timeout Time Unit* and *Connection Timeout Time Unit*. Both default to `MILLISECONDS`. For more information, see xref:oracle-ebs-122-connector-reference.adoc#TcpClientSocketParameterGroup[TCP Client Socket Parameter Group].
* PL/SQL XML binding now uses Jackson XML instead of JAXB.
* XML, XSD, and WADL parsing now rejects unsafe external references, limits XML resource use, and prevents external-entity and XPath-injection paths.
* PL/SQL aliases and operation names that contain unsafe endpoint characters are rejected as `BAD_REQUEST` before an HTTP request is built.
* The *Invoke PL/SQL REST Service* operation error type changes from `ORACLE-EBS122:UNKNOWN` to `ORACLE-EBS122:UNEXPECTED`. Flows that handle the `UNKNOWN` leaf error must be updated. Handlers for the `CONNECTIVITY` parent remain applicable.
* In clustered deployments, *On New Business Event* now runs only on the primary node to avoid competing dequeues from the same AQ queue. For more information, see xref:oracle-ebs-122-connector-reference.adoc#BusinessEventsListener[*On New Business Event*].
* These libraries are upgraded to address reported security vulnerabilities:

** The Apache Commons Lang library is upgraded to version 3.21.0.
** The Apache Commons Collections library is upgraded to version 4.6.0.
** The Oracle JDBC driver is upgraded from `ojdbc8` 19.31.0.0 to `ojdbc10` 19.32.0.0.

== Requirements

Before you upgrade, ensure that your environment meets these requirements:

[%header%autowidth.spread]
|===
|Application/Service |Version
|Mule runtime |4.9.0 and later
|Java |17
|Oracle EBS |12.2.x
|===

== Upgrade Prerequisites

Before you perform the upgrade:

. Create a backup of your files, data, and configuration.
. Upgrade the application's Mule runtime to 4.9.0 or later and use Java 17.
. Update flows that handle `ORACLE-EBS122:UNKNOWN` to handle `ORACLE-EBS122:UNEXPECTED`.
. Rename `business-events-source` to `business-events-listener` in the application XML.
. If a flow reads *Event Data* as a string, convert the binary value.
. If you use a custom *On New Business Event* AQ queue, verify that it uses the `APPS_NE.WF_EVENT_T` payload type.

== Upgrade Steps

. In Anypoint Studio, open your Mule project.
. In the `pom.xml` file, update the `mule-oracle-ebs-122-connector` dependency to version `3.0.0`.
. Update flow error handlers that handle `ORACLE-EBS122:UNKNOWN` to handle `ORACLE-EBS122:UNEXPECTED`.
. Rename `business-events-source` to `business-events-listener` in the application XML.
. If your app uses *On New Business Event* with a custom AQ queue, configure the *Queue owner* and *Queue name* fields.
. Save the project and deploy the app.

== Verify the Upgrade

After you upgrade:

. In Anypoint Studio, verify that there are no errors in the *Problems* or *Console* views.
. Test PL/SQL REST operations and verify their XML payloads and HTTP response attributes.
. If your app uses *On New Business Event*, verify that it consumes events from the configured queue.

== Revert the Upgrade

To revert, change the `mule-oracle-ebs-122-connector` dependency in the project's `pom.xml` file to the previous 2.3.x version. Apps that can't run on Mule runtime 4.9.0 or later and Java 17 must remain on version 2.3.x.
