= PeopleSoft REST Connector 1.0 Reference

PeopleSoft REST Connector calls PeopleSoft Component Interface REST Transport (CIRT) endpoints over HTTPS through the Integration Broker REST listener.

[[Config_ClientCredentialsConnection]]
===== OAuth 2.0 Client Credentials Connection

OAuth 2.0 client credentials connection provider for the PeopleSoft CIRT surface. Use this connection when the Integration Broker REST listener is fronted by an OAuth-secured gateway. Each PeopleSoft installation is self-hosted, so you must override the token URL, client ID, client secret, and scopes in the configuration. For example, on Microsoft Entra ID, the client credentials grant requires the resource default scope `api://<client-id>/.default`. A delegated scope such as `readwrite` is rejected with an invalid_scope error. Other identity providers use their own scope syntax.

== Operations

[[InvokeCirtOperation]]
== Invoke CIRT Operation
`<peoplesoft-rest:invoke-cirt-operation>`

Invokes a Component Interface method through the CIRT contract and returns the classified JSON response. CREATE and SAVE_NESTED automatically run a follow-up GET after the write so the operation can return the persisted graph. GET, FIND, and SAVE_SCALAR return the response from a single request. The connector buffers the full response. This release is tested with `CI_PERSONAL_DATA`, `CI_POSITION_DATA`, `LOCATION`, and `USER_PROFILE`. The Component Interface must be registered and REST-enabled on the target PeopleSoft instance.

[[ReplaceUserProfileIdTypes]]
== Replace User Profile ID Types
`<peoplesoft-rest:replace-user-profile-id-types>`

Replaces the IDTypes collection on an existing USER_PROFILE. The operation gets the current graph, overwrites its IDTypes array with the sorted caller list, and posts the mutated graph with Updatedata. The operation returns the classified Updatedata acknowledgment and does not run a follow-up GET after the write.

Configures the repeatable file-store streaming strategy by which Mule keeps a portion of the stream content in memory. If the stream content is larger than the configured buffer size, Mule backs up the buffer's content to disk and then clears the memory.

[%header,cols="20s,25a,30a,15a,10a"]
|===
| Field | Type | Description | Default Value | Required
| In Memory Size a| Number | Maximum amount of memory that the stream can use for data. If the amount of memory exceeds this value, Mule buffers the content to disk. To optimize performance:

* Configure a larger buffer size to avoid the number of times Mule needs to write the buffer on disk. This increases performance, but it also limits the number of concurrent requests your application can process, because it requires additional memory.

* Configure a smaller buffer size to decrease memory load at the expense of response time. |  |
| Buffer Unit a| Enumeration, one of:

** BYTE
** KB
** MB
** GB | Unit for the *In Memory Size* field. |  |
