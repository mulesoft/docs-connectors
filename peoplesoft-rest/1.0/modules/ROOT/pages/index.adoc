= {connector-name} Connector 1.0

Anypoint Connector for {connector-name} ({connector-name} Connector) enables Mule applications to call PeopleSoft Component Interface REST Transport (CIRT) endpoints over HTTPS. The connector sends JSON requests to the PeopleSoft Integration Broker REST listener (`PSIGW`/`RESTListeningConnector`).

Transport cryptography uses the JVM JSSE/TLS stack, so you can run the connector in a FIPS-mode Anypoint runtime after you install a FIPS-certified security provider on the runtime. The connector does not enable FIPS mode.

For information about compatibility and fixed issues, refer to the {connector-name} Connector Release Notes.

== Before You Begin

include::connectors::partial$t-index-partial.adoc[tags=prerequisites]

You must have access to a PeopleSoft Integration Broker REST listener and credentials for Basic authentication or OAuth 2.0 client credentials. 

This connector requires CIRT services published for the Component Interfaces that your Mule app invokes. This release supports standard CIRT `V1` service routes and message contracts only. Custom service or operation aliases, non-`V1` operation versions, customized message contracts, and custom PeopleCode Component Interface methods are not supported.

== Supported Operations

Use xref:peoplesoft-rest-connector-reference.adoc#InvokeCirtOperation[*Invoke CIRT Operation*] with a CIRT-published, REST-enabled Component Interface and one of these methods:

* CREATE
* GET
* FIND
* SAVE_SCALAR (scalar update that leaves child rowsets unchanged)
* SAVE_NESTED (nested update of the full graph)

Each invocation makes a single CIRT request. For CREATE, SAVE_SCALAR, and SAVE_NESTED, provide an unwrapped Component Interface JSON body. The connector adds the required CIRT request envelope. GET and FIND do not send a request body.

Successful responses retain the PeopleSoft response envelope. CREATE, SAVE_SCALAR, and SAVE_NESTED can return an acknowledgement instead of a complete record. If an application requires the created or updated record, invoke GET explicitly.

You can configure default headers and query parameters for both connection types. An operation-specific value overrides a default with the same name. The connector requests JSON responses by default. You can override the `Accept` header to request another format supported by the published service.

This release does not include:

* DataSense or metadata-driven payload schemas (operation bodies are untyped JSON)
* The legacy `Update User Profile ID Type` and Cancel operations
+
To replace the legacy `Update User Profile ID Type` operation, use Invoke CIRT Operation with the `USER_PROFILE` Component Interface and `SAVE_NESTED`. Supply the required path keys and unwrapped JSON, including the intended `IDTypes` collection. Any collection preparation and subsequent GET request are application responsibilities.
+
Cancel is not available because CIRT is stateless and does not provide a corresponding service operation. Remove or replace existing Cancel operations before migrating.
* Other PeopleSoft surfaces such as Query API, Application Messaging, direct SQL, or file and EDI integrations
* Automatic migration of Oracle PeopleSoft Connector psjoa host, port, and domain-password settings
