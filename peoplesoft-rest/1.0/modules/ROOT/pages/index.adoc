= {connector-name} Connector 1.0

Anypoint Connector for {connector-name} ({connector-name} Connector) enables Mule applications to call PeopleSoft Component Interface REST Transport (CIRT) endpoints over HTTPS. The connector sends JSON requests to the PeopleSoft Integration Broker REST listener (`PSIGW`/`RESTListeningConnector`).

Transport cryptography uses the JVM JSSE/TLS stack, so you can run the connector in a FIPS-mode Anypoint runtime after you install a FIPS-certified security provider on the runtime. The connector does not enable FIPS mode.

For information about compatibility and fixed issues, refer to the {connector-name} Connector Release Notes.

== Supported Component Interfaces

This release supports these CIRT-published Component Interfaces:

* `CI_PERSONAL_DATA`
* `CI_POSITION_DATA`
* `LOCATION`
* `USER_PROFILE`

Use xref:peoplesoft-rest-connector-reference.adoc#InvokeCirtOperation[Invoke CIRT Operation] with one of these CIRT methods:

* CREATE
* GET
* FIND
* SAVE_SCALAR (scalar update that leaves child rowsets unchanged)
* SAVE_NESTED (nested updatedata of the full graph)

CREATE and SAVE_NESTED each perform a write request and then a follow-up GET so the operation can return the persisted graph. GET, FIND, and SAVE_SCALAR each perform a single request.

xref:peoplesoft-rest-connector-reference.adoc#ReplaceUserProfileIdTypes[Replace User Profile ID Types] replaces the `IDTypes` collection on an existing `USER_PROFILE`.

This release does not include:

* Component Interfaces other than the four listed previously
* A scalar Update User Profile operation (the CI does not publish a scalar verb)
* A Find User Profiles operation (the FIND route is used only as the connectivity check)
* DataSense or metadata-driven payload schemas (operation bodies are untyped JSON)
* Other PeopleSoft surfaces such as Query API, Application Messaging, direct SQL, or file and EDI integrations
* Automatic migration of Oracle PeopleSoft Connector psjoa host, port, and domain-password settings
