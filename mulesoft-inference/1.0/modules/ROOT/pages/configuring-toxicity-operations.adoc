= Configuring Toxicity Operations

== Configure the Toxicity Detection by Text Operation

The *Toxicity detection by text* operation analyzes text content to identify harmful, inappropriate, or toxic language using AI-powered content moderation capabilities from supported inference providers.

To configure the *Toxicity detection by text* operation:

include::connectors::partial$t-configure-operations.adoc[]
* *Text*
+
The text content to analyze for toxicity. This can be user-generated content, comments, posts, or any text that needs moderation.
* *Categories*
+
Optional array of specific toxicity categories to check for (e.g., "harassment", "hate", "violence", "sexual", "self-harm").
* *Threshold*
+
Optional confidence threshold for toxicity detection (typically 0.0 to 1.0). Higher values require higher confidence to flag content as toxic.

This is the XML configuration for this operation:

[source,xml]
----
<ms-inference:toxicity-detection-by-text
  doc:name="Toxicity detection by text"
  doc:id="8ba9d534-f801-4ac7-8a31-11462fc5204b"
  config-ref="MuleSoft_Inference_Configuration"
  text="#[payload.text]"
  categories="#[payload.categories]"
  threshold="#[payload.threshold]">
</ms-inference:toxicity-detection-by-text>
----

=== Output Configuration

This operation responds with a JSON payload containing the toxicity analysis results, including overall toxicity score and category-specific scores.

This is an example response for non-toxic content:

[source,json]
----
{
    "flagged": false,
    "categories": {
        "harassment": false,
        "hate": false,
        "violence": false,
        "sexual": false,
        "self-harm": false
    },
    "categoryScores": {
        "harassment": 0.02,
        "hate": 0.01,
        "violence": 0.03,
        "sexual": 0.01,
        "self-harm": 0.00
    },
    "overallScore": 0.03
}
----

This is an example response for flagged toxic content:

[source,json]
----
{
    "flagged": true,
    "categories": {
        "harassment": true,
        "hate": false,
        "violence": false,
        "sexual": false,
        "self-harm": false
    },
    "categoryScores": {
        "harassment": 0.85,
        "hate": 0.12,
        "violence": 0.05,
        "sexual": 0.02,
        "self-harm": 0.01
    },
    "overallScore": 0.85,
    "flaggedCategories": ["harassment"]
}
----

The operation also returns attributes with provider and processing information:

[source,json]
----
{
  "additionalAttributes": {
      "provider": "openai",
      "model": "text-moderation-latest",
      "responseTime": 450,
      "textLength": 156
  }
}
----

== Response Fields

* `flagged`
+
Boolean indicating whether the content was flagged as toxic
* `categories`
+
Object containing boolean values for each toxicity category
* `categoryScores`
+
Object containing confidence scores (0.0-1.0) for each category
* `overallScore`
+
Overall toxicity confidence score
* `flaggedCategories`
+
Array of category names that were flagged (only present when content is flagged)

== Toxicity Categories

The supported toxicity categories may vary by provider but typically include:

* *Harassment*: Content that expresses, incites, or promotes harassing language towards any target
* *Hate*: Content that expresses, incites, or promotes hate based on race, gender, ethnicity, religion, nationality, sexual orientation, disability status, or caste
* *Violence*: Content that promotes, encourages, or depicts acts of violence
* *Sexual*: Content meant to arouse sexual excitement or promote sexual services
* *Self-harm*: Content that promotes, encourages, or depicts acts of self-harm

== Use Cases

Common use cases for toxicity detection include:

* *Content Moderation*
+
Automatically screen user-generated content before publication
* *Social Media Monitoring*
+
Monitor posts, comments, and messages for policy violations
* *Customer Communication*
+
Ensure customer service interactions maintain appropriate tone
* *Community Management*
+
Moderate forum discussions and community interactions
* *Compliance*
+
Meet regulatory requirements for content safety

== Provider Support

* *OpenAI*: Full support for toxicity detection with comprehensive category analysis
* *Mistral AI*: Supports toxicity detection with category-specific scoring
* *Other Providers*: Most other inference providers do not currently support toxicity detection operations

== Best Practices

* Set appropriate thresholds based on your use case and tolerance for false positives/negatives
* Combine automated detection with human review for critical applications
* Regularly review and adjust categories based on your content policies
* Consider cultural and contextual factors when implementing toxicity detection
* Test with diverse content samples to ensure accuracy across different types of text
