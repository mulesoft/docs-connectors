= Upgrading and Migrating Web Service Consumer Connector to Version 3.0

Upgrade Anypoint Connector for Web Service Consumer (Web Service Consumer Connector) from version 2.x to version 3.x.

== Supported Upgrade Paths

[%header,cols="50a,50a"]
|===
|From Version | To Version
|2.x |3.x
|===

== Changes in This Release

* The *Signature digest algorithm* field defaults to `SHA256`. The *Encryption Digest Algorithm* field defaults to `SHA256`. In 2.x both defaults were `SHA1`. You can still set `SHA1`. Applications that sign or encrypt with the previous SHA-1 default must set the digest algorithm to `SHA1`.
+
For more information, see xref:web-service-consumer-reference.adoc#WssSignConfigurationAdapter[WSS Sign Configuration Adapter] and xref:web-service-consumer-reference.adoc#wss-encryption-algorithms-configuration[WSS Encryption Algorithms Configuration].
* On a custom HTTP transport, a request-response Consume that receives a non-empty HTTP error body containing a SOAP fault raises `WSC:SOAP_FAULT`. In 2.x the same response raised `WSC:CANNOT_DISPATCH`. Update error handlers that catch only `WSC:CANNOT_DISPATCH` for those faults.
+
`error.errorMessage.payload` is the SOAP fault. Read the fault text from `error.errorMessage.payload.reason` and the fault detail from `error.errorMessage.payload.detail`. `error.errorMessage.attributes.headers` contains the response protocol headers. `error.errorMessage.attributes.statusCode` contains the HTTP status code. `error.errorMessage.attributes.reasonPhrase` contains the HTTP reason phrase. The same attributes are available when Consume raises `WSC:BAD_RESPONSE` or `WSC:EMPTY_RESPONSE`. The payload of those two errors is empty.
+
For more information, see xref:web-service-consumer-troubleshooting.adoc#read-soap-fault-details[Read SOAP Fault Details].
* On a custom HTTP transport, a one-way operation no longer treats an HTTP error response as a successful result. That request raises `WSC:CANNOT_DISPATCH`. A WSDL or schema request that receives an HTTP error also raises `WSC:CANNOT_DISPATCH`, and the connector doesn't parse the error page as the WSDL or schema. If the connector can't determine whether the operation is one-way, an HTTP error raises `WSC:CANNOT_DISPATCH` as well.
* This version uses `mule-soap-engine` 3.0.3 and doesn't add Spring to the application. SOAP clients use a CXF bus when Spring isn't on the application classpath. If you upgrade from a 2.x version that put Spring libraries on the application classpath and your application used those libraries, add Spring to the application.

== Requirements

Ensure your system meets these compatibility requirements before you perform the upgrade:

[%header%autowidth.spread]
|===
|Application/Service|Version
|Mule runtime |4.9.0 and later
|Java |17
|===

== Upgrade Prerequisites

Before you perform the upgrade, you must create a backup of your files, data, and configurations in case you need to restore them.

== Upgrade Steps

Follow these steps to perform the upgrade:

. In Anypoint Studio, right-click the project and select *Manage Dependencies* > *Manage Modules*.
. Select `Web Service Consumer Connector - Mule 4` and click *Update version*.
. Click *Apply and Close*.
. Verify that the Web Service Consumer Connector dependency version is `3.0.0` in the `pom.xml` file in the Mule project.

Alternatively, you can manually update the Web Service Consumer Connector dependency version in the `pom.xml` file in the Mule project, or simply add the updated connector to the project.

== Verify the Upgrade

After you upgrade the connector, follow these steps to verify the upgrade:

. In Studio, verify that there are no errors in the *Problems* or *Console* views.
. Verify that there are no problems in the project `pom.xml` file.
. Test the connection to verify that the operations work.

== Troubleshoot

If there are problems with caching the parameters and caching the metadata, try restarting Anypoint Studio.

== Revert the Upgrade

If you need to revert to the previous version of Web Service Consumer Connector, change the `mule-wsc-connector` dependency version in the project's `pom.xml` file to the previous version.

You must update the project's `pom.xml` file in Anypoint Studio.
