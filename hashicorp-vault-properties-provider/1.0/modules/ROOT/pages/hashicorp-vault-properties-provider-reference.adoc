= HashiCorp Vault Properties Connector 1.0 Reference

Anypoint Connector for HashiCorp Vault Properties (HashiCorp Vault Properties Connector) enables Mule applications to retrieve configuration properties from HashiCorp Vault.

Select exactly one authentication type: Token, AppRole, or LDAP.

== Configurations
---
[[Config]]
=== Config

Default configuration.

==== Parameters

[%header%autowidth.spread]
|===
| Name | Type | Description | Default Value | Required
|Name | String | The name for this configuration. Connectors reference the configuration with this name. | | x
| Vault Address a| String | Absolute HTTP or HTTPS URL of the Vault server. Include only the origin, with no path. | | x
| Authentication a| One of:

* <<TokenAuthentication>>
* <<AppRoleAuthentication>>
* <<LdapAuthentication>> | Exactly one Vault authentication type: Token, AppRole, or LDAP. | | x
| Secrets Mount a| String | Vault secrets engine mount name for key-value version 2. | secret |
| Vault Namespace a| String | Optional Vault Enterprise or HCP namespace. | |
| Proxy a| <<ProxyConfig>> | Optional HTTP proxy for Vault requests. Host and port are required. | |
| Name a| String | The identifier of this element used to reference it in other components. | | x
| TLS Context a| <<Tls>> | Optional nested Mule `tls:context`, placed as the first child of the configuration, for a custom truststore or mutual TLS to Vault. | |
|===

[[StandardRevocationCheck]]
=== Standard Revocation Check

Configures standard revocation checks for TLS certificates.

[%header,cols="20s,25a,30a,15a,10a"]
|===
| Field | Type | Description | Default Value | Required
| Only End Entities a| Boolean | Which elements to verify in the certificate chain:

* `true`

Verify only the last element in the certificate chain.

* `false`

Verify all elements in the certificate chain. | |
| Prefer Crls a| Boolean | How to check certificate validity:

* `true`

Check the Certificate Revocation List (CRL) for certificate validity.

* `false`

Use the Online Certificate Status Protocol (OCSP) to check certificate validity. | |
| No Fallback a| Boolean | Whether to use the secondary method to check certificate validity:

* `true`

Use the method that was not specified in the *Prefer Crls* field (the secondary method) to check certificate validity.

* `false`

Do not use the secondary method to check certificate validity. | |
| Soft Fail a| Boolean | What to do if the revocation server cannot be reached or is busy:

* `true`

Avoid verification failure.

* `false`

Allow the verification to fail. | |
|===
