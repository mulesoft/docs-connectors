= Upgrading and Migrating AS2 Connector to Version 7.x
:page-aliases: connectors::as2/as2-connector-upgrade-migrate.adoc

Upgrade Anypoint Connector for AS2 (AS2 Connector) from version 6.x to 7.x to take advantage of FIPS-compliant cryptographic support and other improvements.

== Supported Upgrade Paths

Follow the upgrade path in the table.

[%header,cols="50a,50a"]
|===
|From Version | To Version
|6.x |7.x
|===

== Before You Begin

Before you upgrade to AS2 Connector 7.x, make sure you have:

* Mule runtime 4.4.0 or later. See Mule runtime release notes for FIPS support by version.
* AS2 Connector version 7.0.0 or later.
* AS2 Support Libraries version 3.0.0 or later.
* For Non-FIPS mode, Bouncy Castle Java Cryptography Extension (JCE) provider designed for JDK 1.8 or higher. This configuration requires the `bcprov-jdk18on` and `bcpkix-jdk18on` libraries; version 1.82 is recommended.
* For FIPS modes, Bouncy Castle FIPS (BCFIPS) libraries as required by your Mule runtime and security model.
* For FIPS 140-3, Java 17 or later with FIPS-capable JVM when required by your deployment.

== Supported Security Modes

AS2 Connector 7.x supports these security modes, which are controlled by the `mule.security.model` system property:

* **non-fips (default)** – This is the default mode and the connector uses the standard cryptographic libraries (bcprov-jdk18on, bcpkix-jdk18on) that are not FIPS compliant. The system property should not be set for default mode.
* *fips140-2*
+ 
FIPS 140-2 compliant mode. Enabling this security mode configures AS2 Connector to use FIPS 140-2 approved cryptographic providers.
* *fips140-3*
+ 
FIPS 140-3 compliant mode. Enabling this security mode configures AS2 Connector to use FIPS 140-3 approved cryptographic providers.

If the `mule.security.model` property begins with `fips140-`, such as `fips140-2` or `fips140-3`, then AS2 Connector activates FIPS mode and applies the corresponding security controls as shown in the example.

Example for FIPS 140-3:

[source,bash]
----
-Dmule.security.model=fips140-3
----

Mule applications using the AS2 Connector require a Global Element configuration that includes the necessary AS2 Support and cryptographic libraries for each security mode. For FIPS modes, the Mule runtime and BCFIPS requirements still apply. The table provides the AS2-specific libraries.

== Upgrade Steps

Follow these steps to upgrade from AS2 Connector 6.x to 7.x. The configuration changes based on whether you select `non-fips`, `fips140-2`, or `fips140-3` for the security mode.

=== Step 1: Update the Connector Dependency

. Update your project's `pom.xml` file to use AS2 Connector 7.x:

[source,xml,subs=attributes+]
----
<dependency>
    <groupId>com.mulesoft.connectors</groupId>
    <artifactId>mule-as2-connector</artifactId>
    <version>7.0.0</version>
    <classifier>mule-plugin</classifier>
</dependency>
----

.  Rebuild the project and resolve any API or configuration changes reported by the build.

=== Step 2: Add a Connector Configuration Global Element

In 7.x, the application must include only one AS2 Connector External Libs global configuration. Add it as described based on your selected security mode.

==== Configure the Non-FIPS Security Mode

Use this configuration when you're not running in a FIPS-regulated environment. Add the External Libs global configuration and don't set the runtime property explicitly.

**Requirements:**

. Add BouncyCastle jdk18on library v1.82 as an external library.

. Configure the Mule app in Anypoint Studio:

* **In Anypoint Studio:**
.. In the *Package Explorer* or *Canvas*, open your Mule flow or configuration.
.. Click *Global Elements* (or *Create global element* / the plus icon next to Global Elements).
.. Click *Create*, and then search for the *AS2* or *External Libs* option and select *AS2 Connector External Libs - Non FIPS*.
. Name the configuration.
. Clicking *Configure* > *Add recommended libraries* to add the required libraries for your selected security mode.
. Click *OK* to include the libraries as `dependencies` and `sharedLibraries` in the Mule application `pom.xml` file.
. Verity that your project has the required dependencies for your selected security mode. Add the dependencies via Maven if they weren't added automatically.

The image shows the Connector Configuration Global Element and the configurations that must be performed when using the non-fips security mode:
image::as2-connector-upgrade-non-fips-config.png["The non-FIPS default configuration"]

Follow these steps to configure the non-FIPS security mode in XML (Maven or standalone):
. Open your main Mule configuration file, such as `src/main/mule/` or `src/main/resources/`.
. Add the `as2-mule4:external-libs-non-fips-config` global element to the Mule configuration file.
. Add dependencies and sharedLibraries manually as explained below. 
. Add the `AS2 Connector External Libs - Non FIPS` global configuration to your Mule configuration file, as shown in the example:

[source,xml,subs=attributes+]
----
<as2-mule4:external-libs-non-fips-config name="AS2_External_Libs_Non_FIPS" />
----

. Add the required Maven dependencies for your selected security mode to the `pom.xml` file. Refer 
xref:release-notes:connector/as2-connector-release-notes-mule-4.adoc[Release notes] for comptabile versions of dependencies.

[source,xml,subs=attributes+]
----
<dependency>
    <groupId>org.bouncycastle</groupId>
    <artifactId>bcpkix-jdk18on</artifactId>
    <version>${bouncy.castle.jdk18on.version}</version>
</dependency>
<dependency>
    <groupId>org.bouncycastle</groupId>
    <artifactId>bcprov-jdk18on</artifactId>
    <version>${bouncy.castle.jdk18on.version}</version>
</dependency>
<dependency>
    <groupId>com.mulesoft.connectors</groupId>
    <artifactId>as2-bc-non-fips-impl</artifactId>
    <version>${as2.support.library.version}</version>
</dependency>
----

. Add the configuration for `mule-maven-plugin` by including the `sharedLibraries` under build -> plugins -> plugin section of pom.xml.

[source,xml,subs=attributes+]
----
<configuration>
  <sharedLibraries>
    <sharedLibrary>
      <groupId>com.mulesoft.connectors</groupId>
      <artifactId>as2-bc-non-fips-impl</artifactId>
    </sharedLibrary>
    <sharedLibrary>
      <groupId>org.bouncycastle</groupId>
      <artifactId>bcpkix-jdk18on</artifactId>
    </sharedLibrary>
    <sharedLibrary>
      <groupId>org.bouncycastle</groupId>
      <artifactId>bcprov-jdk18on</artifactId>
    </sharedLibrary>
  </sharedLibraries>
</configuration>
----


==== FIPS 140-2

Use this configuration when your environment requires FIPS 140-2 compliant cryptography. Add the External Libs global configuration first, and then set the runtime property.

To configure the global configuration as a Mule app in an environment that requires FIPS 140-2 compliant cryptography:

* BouncyCastle FIPS (BCFIPS) must be available as required by your Mule runtime for FIPS 140-2.
* Ensure BCFIPS is configured in Java Security or via Mule runtime FIPS documentation for your version.

. Configure the Mule app in Anypoint Studio:

* **In Anypoint Studio:**
. In the *Package Explorer* or *Canvas* in Anypoint Studio, open your Mule flow or configuration.
. Click *Global Elements* (or *Create global element* / the plus icon next to Global Elements).
. Click *Create*, and then search for the *AS2* or *External Libs* option and select *AS2 Connector External Libs - FIPS 140-2*.
. Name the configuration.
. Clicking *Configure* > *Add recommended libraries* to add the required libraries for your selected security mode.
. Click *OK* to include the libraries as `dependencies` and `sharedLibraries` in the Mule application `pom.xml` file.
. Verity that your project has the required dependencies for your selected security mode. Add the dependencies via Maven if they weren't added automatically.
 
Below is a screenshot of the Connector Configuration Global Element along with configurations to perform for fips140-2 mode. 
image::as2-connector-upgrade-fips140-2-config.png[FIPS 140-2 configuration]

* **In XML (Maven or standalone):**
. Open your main Mule configuration file (for example, `src/main/mule/` or `src/main/resources/`).
. Add global element `as2-mule4:external-libs-fips140-2-config` manually in Mule configuration xml file.
. Add dependencies and sharedLibraries manually as explained below. 
. Add the AS2 Connector External Libs - FIPS 140-2 global configuration to your Mule configuration file:

[source,xml,subs=attributes+]
----
<as2-mule4:external-libs-fips140-2-config name="AS2_External_Libs_FIPS_140_2" />
----

. Add the required Maven dependencies for your chosen mode to `pom.xml` (see the table below).

[source,xml,subs=attributes+]
----
<dependency>
    <groupId>com.mulesoft.connectors</groupId>
    <artifactId>as2-bc1-fips-impl</artifactId>
    <version>${as2.support.library.version}</version>
</dependency>
----

. Add the configuration for `mule-maven-plugin` by including the sharedLibraries under build -> plugins -> plugin section of pom.xml.

[source,xml,subs=attributes+]
----
<configuration>
  <sharedLibraries>
    <sharedLibrary>
      <groupId>com.mulesoft.connectors</groupId>
      <artifactId>as2-bc1-fips-impl</artifactId>
    </sharedLibrary>
  </sharedLibraries>
</configuration>
----

. In *JVM / Mule runtime*, set the security model to FIPS 140-2 as shown:

[source,bash]
----
-Dmule.security.model=fips140-2
----

. If required by your runtime, configure BCFIPS to use only FIPS-approved algorithms as shown:

[source,bash]
----
-Dorg.bouncycastle.fips.approved_only=true
----

This example shows the Mule runtime startup configuration for FIPS 140-2:

[source,bash]
----
java -Dmule.security.model=fips140-2 \
  -Dorg.bouncycastle.fips.approved_only=true \
  -jar mule-standalone.jar
----

**JVM / Mule runtime:** Set the security model to FIPS 140-3:

[source,bash]
----

[source,bash]
----

----

[source,bash]
----

  -jar mule-standalone.jar
----

[NOTE]
The `org.bouncycastle.fips.approved_only` property is JVM-wide and must be set by your system or runtime configuration when running in FIPS mode.
* If you use BCFIPS in FIPS mode, key and algorithm restrictions apply. Only approved algorithms supported by BCFIPS provider are supported.
=== Step 3: Keystore and Algorithm Compatibility
* Make sure keystores and certificates are compatible with your selected security mode. Some FIPS modes require FIPS-approved algorithms.
* If you use BCFIPS in FIPS mode, key and algorithm restrictions apply; refer to Mule and BCFIPS documentation for approved algorithms.

=== Step 4: Verify Connector Usage in Flows

* Make sure partner certificates and algorithms are compatible with your selected security mode. If you use AS2 Connector operations in the flows, verify that the connector configuration also exists in the Mule app. 

== Configure External Libraries and Validate Startup
When an AS2 listener, AS2 MDN listener, or Send operation starts, AS2 Connector validates that the External Libs configuration and runtime settings are correct. Understanding these checks helps you resolve startup errors.

=== Validations Performed at Startup

Validation fails if the Mule application includes listener, MDN listener, or Send operations that don't meet these configuration requirements:

* *One External Library*
+ 
An error occurs if the application includes more than one external library or doesn't include any.

* *System Property Alignment*
+ 
The `mule.security.model` system property must match the selected External Libs configuration:** For non-FIPS, `mule.security.model` must not be enabled. If it's enabled, you must remove the property.
** For FIPS 140-2, `mule.security.model` must be set to `fips140-2`. If it's not configured correctly, you'll see a message in logs to correct the setting to `-Dmule.security.model=fips140-2`.
** For FIPS 140-3, `mule.security.model` must be set to `fips140-3`. If it's not configured correctly, you'll see a message in logs to correct the setting to `-Dmule.security.model=fips140-3`.  

* *Classpath alignment* 
+ 
The implementation library for the selected security mode must be on the same `classpath`. Startup fails if the expected library is missing. To resolve the issue, review the error log to find the conflicting libraries and remove them from the `classpath`. These are the correct implementation libraries for each security mode:

** Non-FIPS: `as2-bc-non-fips-impl`
** FIPS 140-2: `as2-bc1-fips-impl`
** FIPS 140-3: `as2-bc2-fips-impl`

* *Crypto implementation instantiation*
+ 
AS2 Connector instantiates the cryptographic implementation for the selected security mode at startup. If this fails, for example due to missing or incompatible libraries, the application shows an error that includes the security profile and the cause.


== System Properties Reference

|===
|Property | Description | Values | Default | Scope
|`mule.security.model` | Security mode used by the connector | `fips140-2` or `fips140-3` | `non-fips` (when not set) | Runtime / JVM
|`org.bouncycastle.fips.approved_only` | Restricts BCFIPS to FIPS-approved algorithms only. Required for FIPS compliance when using BCFIPS. | `true`, `false` | `false` | JVM-wide
|===

The `org.bouncycastle.fips.approved_only` property affects the entire JVM. When the application runs in FIPS mode, the system administrator must configure the property. For more information, see xref:mule-runtime::security/fips-140-2-compliance-support.adoc[Mule documentation for FIPS]

== Migrate Existing Deployments

AS2 Connector 7.x introduces a Global Connector Configuration and supports configurable security modes including non-FIPS, FIPS 140-2, and FIPS 140-3 via the `mule.security.model` system property. Follow the upgrade steps for the changes that must be made to the Mule app. AS2 Connector’s cryptographic behavior is determined by the global configuration, which provides the necessary libraries and defines the runtime security model.

Existing 6.x flows remain functional without requiring code changes.

=== FIPS 140-2 or 140-3 Environment

. Verify that BCFIPS and FIPS-related settings are configured correctly for your Mule runtime version. For more information, see 
xref:mule-runtime::security/fips-140-2-compliance-support.adoc[Mule documentation for FIPS]. 
. Set `mule.security.model` to `fips140-2` or `fips140-3` as appropriate for your compliance requirement.
. Set `org.bouncycastle.fips.approved_only=true` when required for compliance.
. Test in a non-production environment: run flows with AS2 Listener, MDN Listener, and Send operations.
. Deploy to production and monitor logs for successful startup and AS2 message exchange.

== Post-Upgrade Steps

. Verify that the application starts without errors and that AS2 Connector initializes correctly for your selected security mode.  
. Test the AS2 listener, MDN listener, and Send operations against your AS2 partners.  
. Confirm that certificates and algorithms are accepted in FIPS mode if applicable.
. Notify partners of URL or port changes if you modified the HTTP Listener configuration.  

== Troubleshooting

These common error messages indicate configuration or `classpath` issues that prevent AS2 Connector from operating in the desired security mode.

* *AS2 Connector requires at least one External Libs configuration*
+ 
Add AS2 Connector External Libs - Non FIPS, AS2 Connector External Libs - FIPS 140-2, or AS2 Connector External Libs - FIPS 140-3 to your application. See <<Validations Performed at Startup>>.
* *Only one External Libs configuration is allowed per application*
+ 
Remove the additional External Libs configurations so that you only have non-FIPS, FIPS 140-2, or FIPS 140-3.* **"Detected 'as2-bc-non-fips-impl' but system property 'mule.security.model' is ...":** For Non-FIPS mode, do not set `mule.security.model`, or remove it from JVM arguments or runtime configuration.
* *Detected 'as2-bc-non-fips-impl' but system property 'mule.security.model' is ...*
+ 
For non-FIPS mode, disable `mule.security.model` or remove it from the JVM arguments or runtime configuration.
* *Detected 'as2-bc1-fips-impl' but system property ... Set -Dmule.security.model=fips140-2*
+ 
Add `-Dmule.security.model=fips140-2` when using AS2 Connector External Libs - FIPS 140-2.
* *Detected 'as2-bc2-fips-impl' but system property ... Set -Dmule.security.model=fips140-3*
+ 
Add `-Dmule.security.model=fips140-3` when using AS2 Connector External Libs - FIPS 140-3.
* *External Libs - ... configuration selected, but '...' is not on the classpath*
+ 
Add the correct implementation dependency for your selected security mode or make sure the External Libs configuration imports the dependency. If you receive a warning, make sure only the library for your active security mode remains on the `classpath` by removing additional AS2 cryptographic implementations.
* *Startup or crypto errors in FIPS mode*
+ 
Make sure `mule.security.model` matches your runtime FIPS setup and that BCFIPS is installed and registered. Set `org.bouncycastle.fips.approved_only=true` if required.
* *Tests or flows that relied on Non-FIPS behavior*
+ 
If your application is running with `mule.security.model=fips140-2` or `fips140-3`, some algorithms or key usages are restricted. Align keystores and partner expectations with FIPS-approved algorithms.
* *Caching or metadata issues*
+ 
If Anypoint Studio or Anypoint Design Center shows a stale configuration, try restarting the IDE or clearing caches.
== Revert the Upgrade

To revert to AS2 Connector 6.x:
. Change the `mule-as2-connector` dependency in your project's `pom.xml` file to the desired 6.x version.
. Remove the Global Element AS2 Connector External Libs - Non FIPS, AS2 Connector External Libs - FIPS 140-2, or AS2 Connector External Libs - FIPS 140-3.
. Remove the libraries that are added as `dependencies` and `sharedLibraries` from the `pom.xml` file.
. Remove or adjust 7.x-specific system properties, such as `mule.security.model`, if they aren't used by other components.
