[[basic-authentication]]
=== Basic Authentication

Enter the authentication information in the *General* tab of the *Global Element Properties* screen to configure Basic authentication:

. Select *Connection > Basic* and enter or set the values for these fields:
+
[%header,cols="30s,70a"]
|===
|Field |User Action
|Name |Enter the configuration name.
|Username | Username used to initialize the session.
|Password | Password used to authenticate the user.
|Preemptive | If set to true, the client sends its authentication credentials (username and password) with the initial HTTP request to the server, rather than waiting for the server to challenge (401 Unauthorized) the client.
|===

[[oauth-auth-code]]
=== OAuth Authorization Code

Used when the client is acting on behalf of an end user (human). For instance, an agent calls an MCP tool implemented by a SaaS system.

[[oauth-client-credentials]]
===  OAuth Client Credentials

Used for machine-to-machine authentication. The client application authenticates itself directly with the authorization server using its client ID and client secret, and receives an access token.

This is used when an application is accessing resources on its own behalf, not on behalf of a user.

[[digest]]
=== Digest

An HTTP authentication scheme that uses a challenge-response mechanism to avoid sending passwords in plain text. It involves hashing the password and other information to verify the client's identity.

[[ntlm]]
=== NTLM

A Microsoft authentication protocol used primarily in Windows environments. It uses a challenge-response mechanism and is commonly used for network authentication.

[[apply-mcp-policies]]
== Apply MCP Policies

MCP Connector has support for policies to enhance security, monitoring, and governance of your MCP server endpoints. You can apply policies to control access, add authentication, implement rate limiting, and provide additional security layers.

Available MCP policies include:

* *MCP Support Policy*
+
Adds MCP support to an Omni Gateway MCP server instance. This policy is required for your MCP server instance to function properly.
* *MCP Schema Validation Policy* 
+
Validates MCP requests to ensure they conform to the MCP specification
* *MCP Attribute-Based Access Control Policy*
+
Controls access to tools, resources, and prompts based on user information such as Tiers, IP, Headers, or Claims

=== Best Practices for MCP Policies

* Always apply authentication policies to production MCP servers.
* Use logging policies to track MCP client activity.
* Implement rate limiting to prevent abuse and ensure fair usage.
* Configure different policies for development, staging, and production environments.
* Periodically review and update policy configurations.

For more information about available policies and their configuration, see xref:gateway::policies-included-directory.adoc[].
